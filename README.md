# 飞书 ↔ 本地 Claude Code 桥接器

在飞书里给机器人发消息 → 本地 `claude` CLI 执行（多轮会话自动续接）→
回复以**流式卡片**实时回传（边生成边更新），工具调用实时转发。**WebSocket 长连接模式，无需公网 IP。**

## 一、前置条件

- 已安装 Claude Code CLI 并登录（终端里 `claude` 能用）
- 已安装 [uv](https://docs.astral.sh/uv/)（或自行用 pip 装依赖）

## 二、飞书开放平台配置（一次性）

进入 [开放平台](https://open.feishu.cn/) → 你的应用（凭据已配在 `.env`）：

1. **添加机器人能力**：应用能力 → 机器人 → 开启
2. **开通权限**（权限管理里搜索并开通）：
   - 「以应用的身份发消息」— 发消息用
   - 「读取用户发给机器人的单聊消息」（*用户发给机器人的单聊消息*）— 收私聊消息用
   - 群聊使用（可选）：搜索「群聊中@机器人」相关权限
   - 群聊免 @（可选，`/listen` 用）：开通「**获取群组中所有消息**」，并在该群发一次
     `@机器人 /listen`；不开此权限则群聊仍需 @ 触发
3. **事件订阅**：
   - 订阅方式选择 **「使用长连接接收事件」**（重要！否则连不上）
   - 添加事件：**接收消息 `im.message.receive_v1`**
   - 添加事件（按钮面板用，可选）：**卡片回传交互 `card.action.trigger`**
   - 添加事件（版本发布通知用，可选）：**应用版本审核结果 `app_version.audit`**
   > 订阅 `card.action.trigger`、`app_version.audit` 后须发布新版本才生效；
   > 不订阅前者则 `/panel` 按钮点了没反应，不订阅后者则无版本发布通知
4. **发布应用**：版本管理与发布 → 创建版本并发布（可用范围建议设为仅自己）

发布后在飞书客户端搜索机器人名字，发起单聊即可。

## 三、配置 .env

至少填一项：

```
ALLOWED_USERS=ou_xxxxxxxx   # 你的 open_id
```

> 留空时机器人会拒绝执行并发给你 open_id，照提示填上重启即可。
> 机器人等于你电脑的远程入口，**务必配置白名单**，别让同事也能操控你的电脑。

其他可选配置（`WORK_DIR`、`CLAUDE_PERMISSION_MODE`、`CLAUDE_TIMEOUT` 等）见 `.env` 内注释。

## 四、运行

```bash
uv sync          # 安装依赖
uv run bot.py    # 启动机器人（保持窗口开着）
```

## 五、使用

- 直接发文本 = 给 Claude 下指令，多轮对话自动保持上下文
- **权限确认走飞书卡片**：非 `bypassPermissions` 模式下，Claude 遇到需要授权的操作
  （如未白名单的命令）不会默默拒绝，而是发一张卡片——点 **✅ 允许 / ❌ 拒绝** 按钮，
  或直接回复文字（`允许` / `拒绝` / 任意说明文字，说明会作为拒绝原因转给 Claude，
  例如"不要删文件，改用备份目录"）。等待**不限时**（与桌面终端一致：卡片一直等你，
  `/stop` 可中断任务；`PERM_TIMEOUT_SECONDS` 可设上限，超时按拒绝处理）。
  原理：`claude --permission-prompt-tool`
  → `perm_mcp.py`（MCP 服务器）→ 本地端口 → 卡片
- **执行中发消息会直接递给 Claude**：每个会话是一个长驻 `claude` 进程（stream-json
  双向），消息直达 stdin，正在跑的任务会在**工具调用间隙**读到它、边跑边回应
  （和桌面终端体验一致，已实测）；进程闲置 15 分钟自动回收（上下文已存盘，随时续接），
  回收前会检查活跃子进程——后台编译/巡检等长任务没跑完不误杀（依赖 psutil，`uv sync` 自动安装）
  `/stop` 中断当前任务，`/unqueue` 取消排队接管
- `!命令` = 直通 shell：在本机 PowerShell 直接执行、回显结果（不经 Claude，
  相当于桌面终端的 `!` bash 模式；超时 120 秒，长任务建议发给 Claude）
- Claude 的回复以**流式卡片**呈现：边生成边实时更新（约 1 秒刷新一次，带"✍️ 正在生成"
  角标，完成自动定格）；超长回复自动分段续卡，内容不丢；执行的命令（🔧 开头）实时转发，
  结束附耗时/费用摘要。觉得过程刷屏可发 `/quiet` 开静默模式（本聊天独立）——
  只在需要你拍板时通知（权限卡片、最终结果、异常）
- 群聊里 @机器人 触发

| 命令 | 作用 |
|------|------|
| `/help` | 查看帮助 |
| `/new` | 开启新会话（清除上下文） |
| `/stop` | 中断正在执行的任务 |
| `/status` | 状态面板：本聊天设置（权限/静默/免@）+ 会话绑定、工作目录、进程工作状态、实时观察 |
| `/session` | 查看会话 ID（在本机 `claude --resume <id>` 可接续） |
| `/sessions [条数]` | 列出电脑上最近的会话（含当前绑定的；默认 8 条，`/sessions 15` 可看更多；用过一段的会话自动带一行摘要，闲置回收后后台生成） |
| `/takeover [序号\|ID\|latest]` | 接管电脑上的会话，带上全部上下文（正在跑的发卡片选：排队/强制/取消；加 `!` 跳过选择直接强制）。**会话独占**：同一会话只归一个聊天，后接管者优先——被挤掉的聊天会解绑并收到通知 |
| `/exit` | 退出当前接管的会话：解绑并回收驻留进程（历史保留，`/takeover` 可重新接管；直接发消息则开新会话） |
| `/peek [序号\|ID\|latest]` | 旁观会话当前进度（正在干什么、最新输出） |
| `/observe [序号\|ID\|latest]` | **实时观察**：快照卡片随转录动静自动刷新（约 15 秒一帧，远程看终端直播）；闲置 5 分钟自动结束 |
| `/unobserve` | 停止实时观察 |
| `/unqueue` | 取消排队接管 |
| `/addcmd 标签 消息` | 添加快捷命令（按钮面板用） |
| `/delcmd 序号` · `/cmds` | 删除 / 查看快捷命令 |
| `/panel` | 发送快捷命令按钮卡片，点按钮即发送对应消息 |
| `/rename [名字]` | 给当前会话起名，`/sessions` 列表优先显示 |
| `/cwd [路径]` | 查看/切换 Claude 的工作目录 |
| `/mode [模式]` | 查看/切换本聊天的权限模式（`manual` `auto` `acceptEdits` `plan` `bypassPermissions`；未设置时用 `.env` 的全局默认，下一条消息生效；驻留进程会自动用新模式重建） |
| `/listen` | 群聊免 @ 模式：本群所有消息直接发给机器人（适合只有你+机器人的群） |
| `/mute` · `/unmute` | 手动暂停/恢复桌面事件推送 |
| `/quiet` · `/unquiet` | 静默模式（本聊天独立）：不转发思考/工具过程，只推权限确认卡片和最终结果 |

> 多项目并行：不同飞书聊天（单聊/不同群）各自绑定独立会话与工作目录，
> 任务/排队/目录互不干扰（A 聊天在跑任务，B 聊天发消息立即执行）；
> 同一个聊天内用 `/sessions` + `/takeover 序号` 在项目间切换。
> 和机器人的**私聊窗口只有一个**，要并行多会话就建几个只有你自己的群
> （群里 `/listen` 开免 @ 后，用起来和私聊一样）。
> `/mode`、`/quiet` 是本聊天独立的设置（权限模式未单独设置时用 `.env` 全局默认）；
> `/mute`（桌面事件推送）是全局的——桌面通知只推给唯一的目标聊天。

## 电脑 ↔ 飞书 会话接力

Claude Code 的会话存在 `~/.claude/projects/` 下的转录文件里，不绑定终端窗口，
所以**电脑和飞书可以接力同一个会话（带上全部上下文），但不能同时使用**：

- 飞书 → 电脑：`/session` 拿到 ID，电脑上 `claude --resume <id>`
- 电脑 → 飞书：`/takeover <id>`（或 `/takeover latest`），工作目录自动跟随会话
- ⚠️ 接力前先让另一端退出（桌面终端 Ctrl+C 退出），两边同时用会"分叉"（见下）

**对正在运行的桌面会话**：CLI 没有向运行中进程注入消息的机制（`claude attach` 是
给人用的终端界面），所以做了两层替代：

- **排队接管**：`/takeover` 时发现会话回合还在跑，会先绑定并进入排队——你发的消息
  自动排队，等它回合结束**自动依次执行**（机器人每条消息都重新 `--resume` 重读转录
  文件，所以等桌面把结果写完再发，上下文完整无缝）。等待上限 30 分钟，`/unqueue` 取消
- **旁观进度**：`/peek [序号|ID|latest]` 随时看它在干什么（最近的用户消息、回复、
  工具调用），正在跑会标 ⚡，跑完标 💤
- **实时观察**：`/observe` 持续盯转录文件，有新动静就把 /peek 式快照**整卡刷新**到
  同一张卡片（约 15 秒一帧，`OBSERVE_REFRESH_SECONDS` 可调）——桌面长任务跑着时
  在飞书里"看直播"。闲置 5 分钟自动定格结束，`/unobserve` 随时停；观察是纯只读
  旁观，不占用会话、不跟排队接管冲突，多个聊天可以各自观察同一个会话；
  接管该会话后观察自动关闭（进度改走流式卡片）。机器人重启后观察自动恢复

**为什么不能两边同时用**（实测结论）：
- `--resume` 不检查会话是否被占用 —— 对正在运行的会话接管会**成功、不报错**，但它是个"分身"：
  读走历史快照、另起进程，与桌面进程互不相见
- 桌面终端**看不到**飞书端的新消息（对话历史在桌面进程内存里，不会重读转录文件），
  两边各自继续就是同一个会话 ID 下两条平行对话，转录文件被交错追加
- 之后任何一方再 resume，都会把交错的"双时间线"整个当作上下文，对话会显得精神分裂
- 机器人已内置防护：会话最近 15 秒内仍在写入时，`/takeover` 会先警告，
  确认没问题可 `/takeover <id>!` 强制接管；`/sessions` 列表也会标出 ⚡ 可能仍在运行的会话
- **多个飞书聊天之间同样独占**：同一会话只归一个聊天（后 `/takeover` 者优先，
  被挤掉的聊天解绑并收到通知）；用完 `/exit` 退出释放，别的聊天即可接管

## 桌面通知（hooks）

`notify.py` 配合 Claude Code 的 hooks：桌面会话**完成回合**或**等你确认权限**时，
自动推送提醒到飞书（含回复摘要、项目名和可复制的 `/takeover` 命令）。

**桌面权限远程确认（`perm_gate.py`，PermissionRequest hook）**：桌面终端跑的任务
卡在权限确认、而人不在电脑前时，确认卡直接推到飞书——手机点 **✅ 允许** 即放行
桌面进程继续跑（❌ 拒绝亦可，回复文字则作为拒绝原因转给桌面 Claude）。人在电脑前
时自动让路（终端照常弹框，零打扰）；超时未应答回退桌面终端弹框。此时 `/peek`、
`/observe` 会显示 **⏸ 桌面端在等你确认权限**，一眼看出"该你输入了"。
（需在 `~/.claude/settings.json` 的 hooks 里挂 `PermissionRequest` → `perm_gate.py`，
timeout 建议 600；确认卡推送到桌面通知目标聊天，等待上限 `PERM_GATE_WAIT` 默认 300 秒。）

**免打扰（双保险）：**
- 自动：检测键鼠活动 —— 你在电脑前（3 分钟内有操作）不推送，离开后才推
  （阈值可在 `.env` 用 `NOTIFY_IDLE_SECONDS` 调整，0=总是推送；权限远程确认同用此阈值）
- 手动：飞书里发 `/mute` 全部暂停，`/unmute` 恢复

其他：
- 首次使用：机器人收到过至少一条消息后，通知目标才会写入 `notify_target.json`
- 机器人自己 spawn 的 claude 不触发通知（环境变量标记，避免重复）
- 排查：看 `notify.log`；不影响桌面会话（任何失败都静默）

## 六、安全须知

- 机器人能操控你的电脑：白名单（`ALLOWED_USERS`）是第一道防线
- 默认权限模式 `acceptEdits`：Claude 可改文件，但跑命令受你 Claude 设置的限制
- `/mode` 可运行时切换（含 `bypassPermissions`）；若设置 `CLAUDE_PERMISSION_MODE=bypassPermissions`：白名单内的人可让 Claude 做任何事，风险自负
- `!命令` 直通 shell **绕过** Claude 的权限模式（等同于你本人坐在电脑前敲命令），仅白名单用户可用

## 七、常见问题

| 现象 | 处理 |
|------|------|
| 提示找不到 claude | `.env` 里设 `CLAUDE_PATH=<claude 的完整路径>` |
| 飞书端 Claude 的命令总弹权限卡（白名单 `Bash(...)` 规则不生效） | Windows 非交互启动的 claude 默认用 PowerShell 工具，`Bash` 规则匹配不到它。机器人会自动探测 Git Bash 并注入 `CLAUDE_CODE_GIT_BASH_PATH` 让飞书端与终端一致；启动日志提示探测失败时，在 `.env` 设 `GIT_BASH_PATH` |
| 收不到消息 | 检查第 2 步：长连接模式是否开启、`im.message.receive_v1` 是否订阅、权限是否开通并重新发布 |
| 会话失效 | 机器人会自动开新会话重试；`/cwd` 切目录会重置会话 |
| 长任务被中断 | 默认不限时；若设过 `CLAUDE_TIMEOUT`，调大或设 0（不限时），挂死用 `/stop` 远程杀 |

本地状态文件（都在机器人目录，删掉即重置）：会话绑定 `sessions.json`、会话名 `names.json`、
会话摘要 `summaries.json`、实时观察 `observe.json`、桌面权限等待标记 `pending_perm.json`、
免 @ 群 `listen.json`、各聊天独立的权限模式 `modes.json` / 静默模式 `quiet.json`。
