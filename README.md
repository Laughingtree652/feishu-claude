# 飞书 ↔ 本地 Claude Code 桥接器

在飞书里给机器人发消息 → 本地 `claude` CLI 执行（多轮会话自动续接）→
Claude 的回复和工具调用实时转发回飞书。**WebSocket 长连接模式，无需公网 IP。**

## 一、前置条件

- 已安装 Claude Code CLI 并登录（终端里 `claude` 能用）
- 已安装 [uv](https://docs.astral.sh/uv/)（或自行用 pip 装依赖）

## 二、飞书开放平台配置（一次性）

进入 [开放平台](https://open.feishu.cn/) → 你的应用（凭据已配在 `.env`）：

1. **添加机器人能力**：应用能力 → 机器人 → 开启
2. **开通权限**（权限管理里搜索并开通）：
   - 「以应用的身份发消息」— 发消息用
   - 「读取用户发给机器人的单聊消息」（*用户发给机器人的单聊消息*）— 收私聊消息用
   - 群聊使用（可选）：搜索「群聊中@机器人」相关权限
3. **事件订阅**：
   - 订阅方式选择 **「使用长连接接收事件」**（重要！否则连不上）
   - 添加事件：**接收消息 `im.message.receive_v1`**
4. **发布应用**：版本管理与发布 → 创建版本并发布（可用范围建议设为仅自己）

发布后在飞书客户端搜索机器人名字，发起单聊即可。

## 三、配置 .env

至少填一项：

```
ALLOWED_USERS=ou_xxxxxxxx   # 你的 open_id
```

> 留空时机器人会拒绝执行并发给你 open_id，照提示填上重启即可。
> 机器人等于你电脑的远程入口，**务必配置白名单**，别让同事也能操控你的电脑。

其他可选配置（`WORK_DIR`、`CLAUDE_PERMISSION_MODE`、`CLAUDE_TIMEOUT` 等）见 `.env` 内注释。

## 四、运行

```bash
uv sync          # 安装依赖
uv run bot.py    # 启动机器人（保持窗口开着）
```

## 五、使用

- 直接发文本 = 给 Claude 下指令，多轮对话自动保持上下文
- Claude 的回复、执行的命令（🔧 开头）都会实时转发回来，结束附耗时/费用摘要
- 群聊里 @机器人 触发

| 命令 | 作用 |
|------|------|
| `/help` | 查看帮助 |
| `/new` | 开启新会话（清除上下文） |
| `/stop` | 中断正在执行的任务 |
| `/status` | 查看任务状态 |
| `/session` | 查看会话 ID（在本机 `claude --resume <id>` 可接续） |
| `/sessions [条数]` | 列出电脑上最近的会话（含当前绑定的；默认 8 条，`/sessions 15` 可看更多） |
| `/takeover [序号\|ID\|latest]` | 接管电脑上的会话，带上全部上下文（加 `!` 跳过"仍在运行"警告） |
| `/rename [名字]` | 给当前会话起名，`/sessions` 列表优先显示 |
| `/cwd [路径]` | 查看/切换 Claude 的工作目录 |
| `/mode` | 查看权限模式 |
| `/mute` · `/unmute` | 手动暂停/恢复桌面事件推送 |

> 多项目并行：不同飞书聊天（单聊/不同群）各自绑定独立会话；
> 同一个聊天内用 `/sessions` + `/takeover 序号` 在项目间切换。

## 电脑 ↔ 飞书 会话接力

Claude Code 的会话存在 `~/.claude/projects/` 下的转录文件里，不绑定终端窗口，
所以**电脑和飞书可以接力同一个会话（带上全部上下文），但不能同时使用**：

- 飞书 → 电脑：`/session` 拿到 ID，电脑上 `claude --resume <id>`
- 电脑 → 飞书：`/takeover <id>`（或 `/takeover latest`），工作目录自动跟随会话
- ⚠️ 接力前先让另一端退出（桌面终端 Ctrl+C 退出），两边同时用会"分叉"（见下）

**对正在运行的桌面会话，只能旁观不能注入**：CLI 没有向运行中会话发消息的机制
（`claude attach` 是给人用的终端界面）。想远程干预，等它回合结束后 `/takeover`。

**为什么不能两边同时用**（实测结论）：
- `--resume` 不检查会话是否被占用 —— 对正在运行的会话接管会**成功、不报错**，但它是个"分身"：
  读走历史快照、另起进程，与桌面进程互不相见
- 桌面终端**看不到**飞书端的新消息（对话历史在桌面进程内存里，不会重读转录文件），
  两边各自继续就是同一个会话 ID 下两条平行对话，转录文件被交错追加
- 之后任何一方再 resume，都会把交错的"双时间线"整个当作上下文，对话会显得精神分裂
- 机器人已内置防护：会话最近 15 秒内仍在写入时，`/takeover` 会先警告，
  确认没问题可 `/takeover <id>!` 强制接管；`/sessions` 列表也会标出 ⚡ 可能仍在运行的会话

## 桌面通知（hooks）

`notify.py` 配合 Claude Code 的 hooks：桌面会话**完成回合**或**等你确认权限**时，
自动推送提醒到飞书（含回复摘要、项目名和可复制的 `/takeover` 命令）。

**免打扰（双保险）：**
- 自动：检测键鼠活动 —— 你在电脑前（3 分钟内有操作）不推送，离开后才推
  （阈值可在 `.env` 用 `NOTIFY_IDLE_SECONDS` 调整，0=总是推送）
- 手动：飞书里发 `/mute` 全部暂停，`/unmute` 恢复

其他：
- 首次使用：机器人收到过至少一条消息后，通知目标才会写入 `notify_target.json`
- 机器人自己 spawn 的 claude 不触发通知（环境变量标记，避免重复）
- 排查：看 `notify.log`；不影响桌面会话（任何失败都静默）

## 六、安全须知

- 机器人能操控你的电脑：白名单（`ALLOWED_USERS`）是第一道防线
- 默认权限模式 `acceptEdits`：Claude 可改文件，但跑命令受你 Claude 设置的限制
- 若设置 `CLAUDE_PERMISSION_MODE=bypassPermissions`：白名单内的人可让 Claude 做任何事，风险自负

## 七、常见问题

| 现象 | 处理 |
|------|------|
| 提示找不到 claude | `.env` 里设 `CLAUDE_PATH=<claude 的完整路径>` |
| 收不到消息 | 检查第 2 步：长连接模式是否开启、`im.message.receive_v1` 是否订阅、权限是否开通并重新发布 |
| 会话失效 | 机器人会自动开新会话重试；`/cwd` 切目录会重置会话 |
| 长任务被中断 | 调大 `.env` 里的 `CLAUDE_TIMEOUT` |

会话记录存在 `sessions.json`（可删除重置全部会话），会话名存在 `names.json`。

## 八、从 GitHub 拉取部署

```bash
git clone https://github.com/Laughingtree652/feishu-claude.git
cd feishu-claude
cp .env.example .env   # 填入你的凭据
uv sync
uv run bot.py
```
